## 新风险记录

### Phase 18 / 包 1 风险
1. **Backward compatibility**: 新增的 request_id/message_trace_id 字段可能影响旧版接收端解析
2. **Auto-assignment conflicts**: 自动分配可能与手动分配冲突
3. **Trace context propagation**: request_id 传递链路可能中断（webhook → pipeline → notify）
4. **Environment variable management**: 新增 CHATFLOW_HANDOFF_AUTO_ASSIGN_OWNER 需要文档说明

### Phase 18 / 包 2 风险
1. **Assignment strategy complexity**: 三种分配模式增加配置复杂度
2. **Round-robin stability**: 基于 session_id 哈希的分配可能不够均匀
3. **Tag mapping parsing**: TAG_MAP 环境变量解析可能失败（格式错误）
4. **Fallback logic**: by_tag 模式的回退逻辑可能不够清晰
5. **Debug metadata bloat**: 新增 assign_mode/assign_reason 字段增加响应大小

### Phase 18 / 包 3 风险
1. **Memory growth**: 进程内分配历史追踪可能造成内存泄漏（有上限控制）
2. **Agent status staleness**: 环境变量中的坐席状态可能过时（需要重启更新）
3. **Least-recent accuracy**: 基于进程内历史的 least_recent 策略在重启后失效
4. **Sticky TTL complexity**: 粘性分配 TTL 逻辑增加分配复杂性
5. **Online agent filtering**: 在线坐席过滤可能意外排除有效坐席
6. **Notification payload growth**: handoff notify 新增字段增加 payload 大小

### Phase 18 / 包 4 风险
1. **File system dependency**: JSONL 落盘依赖文件系统权限和空间
2. **Rotation complexity**: 文件轮转逻辑可能失败（影响后续写入）
3. **Data consistency**: 进程重启可能导致分配历史不完整
4. **Log ID collisions**: assignment_log_id 短哈希可能冲突（低概率）
5. **Performance impact**: 同步文件写入可能影响响应时间
6. **Backup management**: 备份文件积累可能占用磁盘空间
