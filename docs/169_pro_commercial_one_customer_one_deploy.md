# ChatFlow Pro — 商业交付模型（一客户一套部署）

## 决策

**一客户 = 独立部署实例**（自有主机 / 自有容器 / 自有 PaaS 应用）。**密钥与 token 只存在于该实例的环境**（或客户密钥托管），**不**进入共用源码仓库、**不**与另一客户混用同一进程内配置。

与「单集群多租户共库」相对：后者可作为未来产品线，**不是**当前 Pro 默认交付形态。

## 可售卖 MVP（当前工程真值）

交付物建议打包为：

| 组成 | 说明 |
|------|------|
| **运行时** | `src/` Node 服务；`Dockerfile` + `docker-compose.yml` |
| **配置** | `.env.example` + 客户现场 `.env`（gitignore） |
| **文档** | **`docs/168`** 两天清单；**`docs/162`** 客户凭据；**`docs/161`** notify；**`docs/158`** / **`docs/155`** 门禁 |
| **自检** | `npm run check:go-live`；CI 同构 |

客户填 **自己的** 七通道 token、webhook 公网 HTTPS、可选 notify URL 后即可接流量。

## 产品命名（对外）

- **ChatFlow Pro**：多通道 **AI 接待 / 客服自动化**（入站 + 回复 + 留资 + 转人工信号 + 可选外呼）。  
- **不**默认承诺「完整坐席工作台 UI 套件」；坐席侧可由 **notify → 客户 CRM/工单** 承接，或另立项 **管理端/坐席端** 商品。

## 加速路线（与开发并行）

1. **交付包标准化**：固定「镜像 tag + 发行说明 + docs/168」为每次发版出口。  
2. **每客户部署 Runbook**：**`docs/170_pro_customer_ops_runbook.md`**（HTTPS、备份、升级、回滚）。  
3. **第二曲线（可选）**：统一计费/许可、多租户控制面、商用管理 UI — **单独立项**，不阻塞 ①②。
