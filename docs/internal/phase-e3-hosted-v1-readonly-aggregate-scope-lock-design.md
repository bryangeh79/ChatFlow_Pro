## 唯一要答清的问题（钉死）

**在 E1（签核面）与 E2（检查项与证据规格）都已成立的前提下，E3 到底补什么，且为什么不能被 E1 / E2 / D-C4 替代？**

**答**：E1 解决 **人怎么签、签什么栏目**；E2 解决 **每一项的稳定键、证据长什么样、环境格与前置逻辑** — 二者均为 **文档真源**，**不**提供「一次拉齐多路只读信号」的 **机器可读快照**。E3 若立项实现，只补一层 **可选的只读聚合**：把 **已存在的**健康探测结论、**迁移 ledger 只读对账摘要**、**D-C4C governance bundle 运行结果（若在本环境跑过）** 等 **拼成一份报告工件**，降低签核人 **跨系统逐条复制** 的成本，并 **减少**「漏贴某一类证据」的 **人为失误**。  

**不**替代签核：**报告 ≠ Go**。**不**扩展 D-C4：**D-C4 已 closed**，E3 **不得**以 D-C4D 名义扩线；**不**把 E2 注册表改成「可执行策略引擎」— E2 **仍**是规格，E3 **至多**是 **消费** `chk_id` / `kind` 的 **只读**展示层（若实现时出现映射表，须在 **E3 实现 Go** 内交付，**不在**本设计轮实现）。

| 能力 | E1 | E2 | D-C4（含 D-C4C bundle） | E3（本设计所指） |
|------|----|----|-------------------------|------------------|
| 人类签核模板 | ✅ | ❌ | ❌ | ❌ |
| `chk_id` / 证据字段 / 环境矩阵 | ❌ | ✅ | ❌ | ❌（**可消费**，不重新定义） |
| 恢复后只读核查 / 决策 / CI 恢复子集 | ❌ | 仅 **引用**为证据类型 | ✅ **已交付且 closed** | ❌ **不**复制 R1–R7 **职责** |
| **多源只读拼盘 + 统一报告工件** | ❌ | ❌ | bundle **自身**是 **单一**链 | ✅ **唯一**新增价值（**若**实现） |

## [1] E3 Problem Statement

- **问题**：签核人依赖 **多条**只读信号（健康、迁移、CI bundle 等），手工汇总 **易漏、难对表、难复用同一快照 ID**。  
- **目标**：定义 **极小** E3 包 — **只读聚合**、**无写路径**、**不**默认变成 **唯一**门禁 — 实现落地见 [`phase-e3-hosted-v1-readonly-aggregate-report-spec.md`](./phase-e3-hosted-v1-readonly-aggregate-report-spec.md)。  
- **非目标**：**不**解决恢复修复、**不**替代 D-C4A 手跑、**不**替代书面签核、**不**宣称「绿即 v1」。

---

## [2] Why E1 / E2 / D-C4 Are Not Enough

### 对 E1

- 模板 **故意**保留 `<LINK>` 与自由备注；**不**承担「从环境自动拉取当前值」的职责。  

### 对 E2

- E2 规定 **证据应长什么样**、**哪些 `chk_id` 在何环境为 B/M/E**；**不**规定 **如何**从运行时 **生成**该证据（**避免**规格与工具耦合偷跑 gate）。  

### 对 D-C4（含 D-C4C bundle）

- D-C4 **问题域**是 **恢复 / rollback / 一致性治理**；D-C4C bundle 是 **该域**在 CI 的 **只读回归子集**，**已**随 D-C4 **closeout 封存**。  
- **全量 hosted v1** 门禁 **>** bundle；把 E3 **无设计**并入 bundle 会：**混淆**「恢复子集绿」与「上线全表齐」、**侵犯** closed 边界、**诱使**静默扩大 CI **语义** — **故禁止**。

---

## [3] E3 Boundary Lock

| 边界 | 内容 |
|------|------|
| **对 E1** | **不**改签核模板 **结构**；**不**把模板改为「仅脚本输出即可签」。最终 **Go/No-Go** **仍**须 **人**在模板 **E/F** 落笔。 |
| **对 E2** | **不**新增 `chk_id` 语义、**不**改环境矩阵 **含义**；E3 **若**输出映射，**须**单向 **引用** E2，**禁止**反向改 E2 真源。 |
| **对 D-C4C bundle** | **禁止无设计合并**：**不得**在未单独 **E3 实现 Go + 设计评审** 的前提下，把 E3 逻辑 **塞进** `verify-d-c4c-readonly-governance-bundle` 或等同物 **成员列表**；**若**未来要 **编排**同一 CI job，**须**独立 ADR 与 **显式**清单（**非**本文件实现）。 |
| **对 D-C4 全族** | **不** reopen D-C4；**不**新增 D-C4A/B/C **语义**；**仅**允许 **只读调用/展示** **已有**命令或 HTTP 的 **公开输出**（实现阶段再定，**本设计不**写具体命令）。 |
| **对「自动化 gate」** | E3 **默认**定位为 **辅助取证 / 本地或 CI 可选报告** — **不是**「失败即阻断发布」的 **唯一**依据；**若**组织要把输出接 CI，**须**单独 **书面**批准，**且**不得 **削弱** Phase E §4 签核与 §6 No-Go。 |
| **对修复器 / 补偿器** | **禁止**任何写 DB、写 ledger、repair、apply、D-C3B 类路径 — **不是** D-C3C / 修复器 **换名**。 |

### 红线（必须同时满足）

- **只读聚合**；**无写路径**。  
- **不默认**新增 `verify:*`、**不默认**新增 `npm scripts`、**不默认**自动化 gate、**不默认**业务代码、**不默认**新基础设施（Redis/队列/cron 等）。  
- **本设计轮**：**零**代码、**零**脚本落地。

## [4] Candidate Scope Options（必须极小）

| ID | 候选（**若**进入 E3 **实现**轮） | 交付形态（设计 → 未来实现） |
|----|----------------------------------|-----------------------------|

**默认不包含**：新 Admin API、租户面 UI、后台任务、修改 `go-live-check.ts` **语义**。

## [5] Go / No-Go Conditions

### 可进入 **E3 实现** 的条件（**另一次** Bryan 显式 Go）

- 范围 ⊆ **§4 E3-a ~ E3-d**（或 **更小**）；  
- 实现 **必须**保持 **只读** + **无写路径**；  
- **任何** `verify` / `npm script` / CI 接入 **须**在实现包 **单独**列出并 **单独**评审 — **不**默认本设计 **授权**创建它们。

### 应 **停留在设计** 的条件

- 讨论变成「顺便接 D-C4C bundle 一条命令」**而无**合并设计与 ADR；  
- 要求 **失败阻断发布流水线** **且**同步 **削减**人工签核。

### **E3 根本不该立项** 的信号

- 组织 **明确禁止**任何聚合工具，**只**接受纯人工；或  
- 真实诉求是 **修复器 / 自动补偿 / 批量 repair** — 应 **退回** D-C3C 或 **新 ADR**，**不是** E3。

---

## [6] Risks of Mis-scoping

- **报告当 Go**：把聚合输出 **等同**签核完成 — **禁止**；须在实现文档 **重复** Phase E §4。  
- **Bundle 污染**：无设计合并 D-C4C — **违反** closed 边界与主设计 §7。  
- **规格耦合**：E3 实现 **反向**改 E2 `chk_id` 含义 — **禁止**。  
- **Secret 泄漏**：聚合路径 **必须**继承 E2 `contains_secrets=false` 纪律。  
- **Gate creep**：先「只读报告」后默认 `verify:e3` 阻断 — **须**每次 **显式** Go。
