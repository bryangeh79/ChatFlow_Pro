# Phase 13.2 JSONL Backup Cleanup

## Overview
This phase adds automatic cleanup of old backup files generated by the JSONL rotation mechanism. The system now enforces limits on both the number of backup files and their total size to prevent unbounded disk usage.

## Problem Statement
In Phase 11.47, JSONL file rotation was implemented with the following behavior:
- When `local-captured-leads.jsonl` reaches 5MB or 10,000 lines, it's rotated
- Rotated file is renamed to `local-captured-leads.jsonl.backup-{timestamp}`
- New empty file is created for future writes

**Issue**: Over time, backup files accumulate without limit, consuming disk space.

## Solution: Dual-Limit Backup Cleanup
Added `cleanupOldBackups()` function that enforces two limits:

### 1. Count Limit
- **Maximum backups**: 5 files
- **Strategy**: Keep the 5 most recent backup files (by modification time)
- **Rationale**: Recent backups are most valuable for recovery

### 2. Size Limit  
- **Maximum total size**: 50MB across all backups
- **Strategy**: If total size exceeds limit, delete oldest files until under limit
- **Rationale**: Prevent excessive disk usage even with few but large backups

### 3. Combined Enforcement
The cleanup algorithm:
1. List all backup files sorted by modification time (newest first)
2. If count ≤ 5 AND total size ≤ 50MB → no cleanup needed
3. Otherwise:
   - Keep newest 5 files initially
   - If those 5 files still exceed 50MB, delete oldest among them until under limit
   - Delete all files beyond the kept set

## Implementation Details

### Files Changed
1. **`src/channels/lead-capture-hook/persistence.ts`**:
   - Added backup cleanup constants: `MAX_BACKUP_COUNT = 5`, `MAX_BACKUP_TOTAL_SIZE = 50MB`
   - Added `cleanupOldBackups()` function with dual-limit enforcement
   - Modified `performRotation()` to call cleanup after rotation
   - Modified `appendCapturedLeadRecord()` to always attempt cleanup (defensive)

### Cleanup Logic (`cleanupOldBackups()`)
```typescript
// 1. Get all backup files sorted by modification time (newest first)
const backupFiles = files
  .filter(file => file.startsWith(`${baseName}.backup-`))
  .map(file => ({ name: file, path: path.join(dataDir, file), stats: fs.statSync(...) }))
  .sort((a, b) => b.stats.mtimeMs - a.stats.mtimeMs);

// 2. Check if cleanup needed
if (backupFiles.length <= MAX_BACKUP_COUNT && 
    totalSize <= MAX_BACKUP_TOTAL_SIZE) {
  return; // No cleanup needed
}

// 3. Apply count limit (keep newest MAX_BACKUP_COUNT files)
const filesToKeep = backupFiles.slice(0, MAX_BACKUP_COUNT);
const filesToDelete = backupFiles.slice(MAX_BACKUP_COUNT);

// 4. Apply size limit (if kept files still exceed size limit)
let currentTotalSize = filesToKeep.reduce((sum, file) => sum + file.stats.size, 0);
let index = filesToKeep.length - 1;

while (currentTotalSize > MAX_BACKUP_TOTAL_SIZE && index >= 0) {
  const fileToRemove = filesToKeep[index];
  filesToDelete.unshift(fileToRemove);
  currentTotalSize -= fileToRemove.stats.size;
  index--;
}

// 5. Delete files
for (const file of filesToDelete) {
  fs.unlinkSync(file.path);
}
```

### Error Handling
- **Silent failure**: All cleanup errors are caught and logged, but don't affect webhook responses
- **Defensive programming**: Each file deletion is wrapped in try-catch
- **Logging**: Debug logs in development mode, error logs always

## Integration Points

### 1. After Rotation (`performRotation()`)
```typescript
fs.renameSync(filePath, backupPath); // Create new backup
fs.writeFileSync(filePath, ''); // Create new empty file
cleanupOldBackups(filePath); // Clean up old backups
```

### 2. Defensive Check (`appendCapturedLeadRecord()`)
```typescript
rotateJsonlFileIfNeeded(filePath); // Check and rotate if needed
cleanupOldBackups(filePath); // Always check cleanup (even if no rotation)
```

**Why defensive check?**: Ensures cleanup happens even if:
- Manual file operations created backups
- Previous cleanup failed
- System was restored from backup

## Testing Considerations

### Backup Scenarios
1. **Normal operation**: <5 backups, <50MB total → no cleanup
2. **Count limit exceeded**: 10 backup files → keep newest 5, delete oldest 5
3. **Size limit exceeded**: 3 backup files but total 60MB → delete oldest until <50MB
4. **Both limits exceeded**: 8 backup files, total 80MB → apply both limits

### Edge Cases
- **Empty data directory**: No backups exist → no action
- **Permission issues**: Log error but continue
- **Concurrent access**: File system operations are synchronous; minimal risk in single-process deployment

## Configuration Constants

| Constant | Value | Purpose |
|----------|-------|---------|
| `MAX_BACKUP_COUNT` | 5 | Maximum number of backup files to retain |
| `MAX_BACKUP_TOTAL_SIZE` | 50MB | Maximum total size of all backup files |
| `JSONL_MAX_SIZE_BYTES` | 5MB | Main file size trigger for rotation |
| `JSONL_MAX_LINES` | 10,000 | Main file line count trigger for rotation |
